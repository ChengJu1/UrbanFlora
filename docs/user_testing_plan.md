# User Testing Plan

This is the user testing plan I will run with three participants — one per
persona — to see whether the core capture-to-codex loop holds up in real use.

## Participants

- P1, 22–30, student — maps to **Li Wei**
- P2, 45–65, casual park walker — maps to **Chen Ayi**
- P3, 28–35, technical/research background — maps to **Marcus**

## Setup

- Physical Android or iOS device with the release build installed
- Fresh install (prefs cleared) so every participant sees onboarding
- Think-aloud protocol; observer takes timed notes

## Tasks

1. Open the app for the first time and reach the Home dashboard.
2. Take a photo of any plant you can see and add it to your codex.
3. Open yesterday's find (seeded) and read where it was taken.
4. Sign out and sign back in anonymously.

For each task we record:

- **TCT** — Task Completion Time (seconds)
- **Errors** — number of wrong taps / dead ends
- **Help requests** — did they ask the observer anything?

## Post-test: SUS Questionnaire

Ten standard SUS statements, 1-5 Likert. Target ≥ 68 in the first round and
≥ 75 once the rough edges are smoothed.

1. I think that I would like to use this app frequently.
2. I found the app unnecessarily complex.
3. I thought the app was easy to use.
4. I think that I would need the support of a technical person to use it.
5. I found the various functions in the app were well integrated.
6. I thought there was too much inconsistency.
7. I would imagine that most people would learn to use this app very quickly.
8. I found the app very awkward to use.
9. I felt very confident using the app.
10. I needed to learn a lot of things before I could get going.

## Iteration commitments

After each session I commit one refinement before the next, so changes flow
back into the build instead of waiting for one big revision at the end.
